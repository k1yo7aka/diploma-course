# Дипломный проект — Пентест NordLogix Group

**Роль: Атакующий**

---

## 1. Выбранный сценарий и обоснование

**Сценарий:** Black-box пентест внешней инфраструктуры вымышленной компании.

**Обоснование:**

- Роль атакующего — практическая основа пентеста, подойдет для вставки в резюме
- Не требует больших ресурсов
- Охватывает полный жизненный цикл атаки: разведка → эксплуатация → отчёт
- Результат — реальный отчет, полезный опыт в ИБ в целом, особенно для пентестера

---

## 2. Название компании и краткое описание деятельности

**Название:** NordLogix Group

**Деятельность:** Логистическая B2B-компания — платформа для отслеживания грузов и управления цепочками поставок. ~200 сотрудников, офисы в трёх городах. Публичный корпоративный сайт и REST API для партнёров.

---

## 3. Схема инфраструктуры

```
[Internet / Attacker]
    Kali Linux VPS
         |
        FW1 (pfSense/iptables)
         |
       [DMZ]
    ├── Web Server       — nginx + PHP (WordPress CMS)
    ├── API Gateway      — Node.js (REST API для партнёров)
    ├── Mail Server      — Postfix (корпоративная почта)
    └── VPN Gateway      — OpenVPN (удалённый доступ сотрудников)
         |
        FW2 (pfSense/iptables)
         |
    [Internal LAN]
    ├── DB Server        — PostgreSQL
    ├── AD / LDAP        — Windows Server 2019 (Active Directory)
    ├── Jenkins CI/CD    — Ubuntu
    └── File Server      — Samba
```

| #   | Severity     | Уязвимость                      | Суть                                                                                 |
| --- | ------------ | ------------------------------- | ------------------------------------------------------------------------------------ |
| 1   | **Critical** | SQL Injection (Web / API)       | Непараметризованные запросы в форме трекинга груза. CVSS 9.8, прямой доступ к БД     |
| 2   | **High**     | Outdated CMS (WordPress 5.x)    | Known CVE: XML-RPC брутфорс, RCE через уязвимые плагины. CVSS 8.1                    |

| 6   | **Low**      | Exposed .git директория         | Исходный код и .env файлы с credentials в публичном доступе                          |

## 5. Детальный план работ по этапам

### Этап 1 — Разведка (Reconnaissance)

- OSINT: домен, DNS-записи, whois
- Поиск утечек credentials (Pastebin, GitHub dorks)
- Сбор email-адресов сотрудников
- Сканирование открытых портов и сервисов (nmap, masscan)
- **Цель:** составить карту поверхности атаки

### Этап 2 — Сканирование и перечисление

- Веб-поверхность: Nikto, dirb/gobuster — поиск скрытых директорий и уязвимых эндпоинтов
- Анализ API: BurpSuite — перехват и анализ запросов, поиск IDOR и инъекций
- SMB/AD перечисление: enum4linux, crackmapexec
- Проверка версий CMS и плагинов: WPScan
- Обнаружение .git, .env, резервных файлов
- **Цель:** подтвердить наличие конкретных уязвимостей

### Этап 3 — Эксплуатация уязвимостей

- SQLi: SQLMap для автоматизации, извлечение данных из PostgreSQL
- RCE через уязвимый WordPress-плагин: Metasploit / ручной эксплоит
- Credential stuffing на VPN Gateway: Hydra с утёкшими паролями
- Phishing через SMTP Open Relay (вектор социальной инженерии)
- **Цель:** получить первоначальный доступ (foothold) в DMZ

### Этап 4 — Пост-эксплуатация

- Privilege escalation: LinPEAS, sudo -l, SUID-бинари
- Lateral movement: Jenkins (RCE в пайплайне) → доступ к Internal LAN
- Атака на Active Directory: Kerberoasting, Pass-the-Hash, dump LDAP
- Сбор credentials и данных с File Server (Samba)
- **Цель:** максимизировать доступ, достичь Domain Admin

### Этап 5 — Отчётность

- Executive Summary: описание критических рисков для менеджмента
- Технический отчёт: каждая уязвимость с PoC (скриншоты, payload'ы, CVSS-оценки)
- Рекомендации по устранению: патчинг, WAF, MFA, сегментация, hardening
- **Цель:** закрыть работу документом, пригодным для реального заказчика
